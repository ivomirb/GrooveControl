# Contributing to Groove Control

Thank you for your interest in contributing to **Groove Control**! Whether you're reporting bugs, improving documentation, or writing code, we welcome your contributions. Please take a moment to review this document before you begin contributing.

## How to contribute

### Reporting bugs

The best way to report a bug is on the [GitHub Issues](https://github.com/ivomirb/GrooveControl/issues) page.
Provide detailed information, including:
* Steps to reproduce the issue
* Expected behavior
* Actual behavior
* Screenshots or error logs, if applicable
* Version of Groove Control and environment details (OS, hardware, etc.)

### Feature requests

You have a great idea for a new feature? I would like to hear about it.
Post it on the [GitHub Ideas](https://github.com/ivomirb/GrooveControl/discussions/categories/ideas) page.

### Submitting pull requests

Groove Control welcomes pull requests (PRs) for fixes, features, and improvements!
- Ensure your PR is focused on one change (fix, feature, or improvement).
- For simple changes include a detailed explanation what the change does and why it is needed.
- For more complex changes it's best to start a [Discussion](https://github.com/ivomirb/GrooveControl/discussions) first, maybe even before you write the code.
- Ensure the code adheres to the existing style.
- Try to target the appropriate release branch if possible (see below).

### Branching strategy

The **master** branch is intended to reflect the state of the latest release.
Direct submissions are limited to updating the website and documentation.

Each major release has its own branch (**release1.0**, **release1.1**).

Urgent fixes should go to the branch for the current release and will be included in the next minor update.

Larger changes should normally target the next major release.
Depending on the scope, I may decide to spin up a new branch just for it.

Is any of this a good idea? I don't know. I am making it up as I go. It remains to be seen.

### AI-generated code

While I myself do not partake (this is a hobby project, and I don't find AI coding fun), you are welcome to submit such code.

However - keep in mind that every line will be hand-examined and tested before it goes in. Since AI code tends to be on the verbose side, the process will take longer.
Code that is overly complicated or boilerplaty will be mercilessly simplified.
